ข้อจำกัดที่พบและสิ่งที่ปรับแล้ว

  • คนตัวเล็ก/อยู่ไกลหลุดบ่อย: เปลี่ยนตัวตรวจจับหลักเป็น YOLOX-Nano (สัญญาอนุญาต Apache-2.0 ทำงานบน WASM ไม่ต้องใช้ WebGL) เร็วเท่าเดิมแต่เห็นคนตัวเล็กมากขึ้นชัดเจน COCO-SSD ยังเป็นตัวสำรอง คนที่สูงไม่ถึง 1/10 ของภาพยังหลุด ตัวเลือก “คนตัวเล็ก/อยู่ไกล” แบ่งภาพตรวจได้ แต่ช้าลง
  • รหัสสลับเมื่อคนเดินสวนกัน ทำให้นับข้ามเส้นเกิน ตัวติดตามใหม่จับคู่สองขั้น (กล่องมั่นใจก่อน แล้วจึงกล่องคะแนนต่ำ) มีแถบกันสั่นรอบเส้น และต้องอยู่ฝั่งใหม่ 2 เฟรมจึงนับ นับแล้วถูกจริงเพิ่มจาก 72% เป็น 81–91% แต่ในฝูงชนนับขาดมากขึ้น
  • ลดการนับซ้ำ (re-ID) ตัดยอดลง 5–15% ช่วยเมื่อคนเดินวนแถวประตู แต่ทำให้นับขาดมากขึ้นในที่คนแน่น จึงปิดไว้เป็นค่าเริ่มต้น
  • ใบหน้า: กฎรอบ 5: เกณฑ์ปรับตามระยะห่างของใบหน้าในกลุ่มที่ลงทะเบียน (ใบหน้าเอเชียได้เกณฑ์เข้มขึ้นเอง) ตรวจคุณภาพภาพ ยืนยัน 2 เฟรม ลงทะเบียน 3 ท่า และขอให้กดยืนยันเมื่อไม่แน่ใจ คนนอกถูกเสนอชื่อราว 1% หรือน้อยกว่าทุกขนาดกลุ่ม 5–200 คน แต่ใบหน้าเอเชียจำได้เพียง 66–76% · คำแนะนำเดิมเรื่องจำนวนผู้ลงทะเบียนสูงสุดถูกยกเลิกแล้ว เพราะกลุ่มเล็กต่างหากที่เสี่ยงกว่า: ลงทะเบียนอย่างน้อย 5 คนก่อนใช้เช็คชื่ออัตโนมัติ คงการกดยืนยันไว้ และลงทะเบียนคนเดิมใหม่ด้วย 3 ท่า
  • อายุ/เพศ/อารมณ์เป็นการคาดคะเน ใช้ดูภาพรวมกลุ่มผู้ชม ไม่ใช้ตัดสินเรื่องของคนใดคนหนึ่ง

ตรวจความแม่นยำหน้างานให้ผล 2 ระดับ: “ผ่านระดับนำร่อง” ใช้เป้าที่ผ่อนลงและช่วงความเชื่อมั่น 90% ซึ่งเก็บข้อมูลได้ครบในวันเดียว (เช่น คนผ่านเส้น 50–100 ครั้ง หรือขวดดี 30 + ขวดเสีย 25 ขวด) ใช้ตัดสินว่าทดลองต่อได้ ส่วน “ผ่าน (ยืนยันแล้ว)” ใช้เป้าเต็มและช่วงความเชื่อมั่น 95% ต้องเก็บข้อมูลมากกว่ามาก ผลนำร่องไม่ใช่การรับรองความแม่นยำ

วิธีวัด ตารางเต็ม และสัญญาอนุญาตของชุดข้อมูล อยู่ในไฟล์ ACCURACY.md ของโปรเจกต์ (สคริปต์วัดซ้ำได้ใน tests/bench) ชุดข้อมูลใช้เพื่อการประเมินเท่านั้น ไม่ได้รวมไว้ในโปรแกรม: MOTChallenge (CC BY-NC-SA 3.0), LFW และ CASIA-FaceV5 (เพื่อการวิจัย), UTKFace (วิจัยที่ไม่ใช่เชิงพาณิชย์), HaGRID (CC BY-SA 4.0), Open/Closed Eyes (ODC-BY), CEW และ FER-2013 (เพื่อการวิจัย) — ขวดและบาร์โค้ดเป็นภาพจำลองที่สร้างเอง

ใช้งานบนมือถือและแท็บเล็ต

เบราว์เซอร์บนมือถืออนุญาตให้ใช้กล้องเฉพาะเว็บที่เปิดผ่าน https:// เท่านั้น ให้เปิดเซิร์ฟเวอร์ในโหมดมือถือดังนี้

  1. ให้คอมพิวเตอร์ที่รันระบบและมือถืออยู่ใน Wi‑Fi เดียวกัน
  2. บนคอมพิวเตอร์ เปิด Terminal ที่โฟลเดอร์โปรเจกต์ แล้วรัน ./start.sh mobile
  3. หน้าจอจะแสดงที่อยู่ เช่น https://192.168.1.20:8443 ให้พิมพ์ที่อยู่นั้นในเบราว์เซอร์มือถือ (Safari หรือ Chrome)
  4. ครั้งแรกจะมีคำเตือนเรื่องใบรับรอง เพราะเป็นใบรับรองที่สร้างเอง ให้กด “ขั้นสูง/แสดงรายละเอียด” แล้วเลือก “ไปต่อ/เยี่ยมชมเว็บไซต์นี้”
  5. เมื่อเปิดหน้าที่ใช้กล้อง ให้กด “อนุญาต” การใช้กล้อง และใช้ปุ่มสลับกล้องหน้า/หลังได้

หลายกล้องพร้อมกันใช้ได้บนคอมพิวเตอร์ (สูงสุด 4 ตัว) มือถือส่วนใหญ่เปิดได้ทีละกล้อง — ใช้ 1 เครื่องต่อ 1 จุด

ข้อมูลสถิติจะถูกเก็บในเบราว์เซอร์ของแต่ละเครื่องแยกกัน ใช้โหมดนี้เฉพาะในเครือข่ายที่ไว้ใจได้ สำหรับติดตั้งใช้งานจริงแบบถาวร แนะนำให้ใช้โดเมนพร้อมใบรับรอง HTTPS จริง

ใช้มือถือหลายเครื่องรวมยอดเดียว (วิเคราะห์หน้าร้าน)

ตั้งมือถือหรือแท็บเล็ต 1 เครื่องต่อ 1 จุด (ประตูหน้า ประตูหลัง โซนสินค้า) แล้วให้คอมพิวเตอร์ในร้านเป็นเครื่องหลักที่รวมยอด

  1. บนคอมพิวเตอร์เครื่องหลัก รัน ./start.sh mobile หน้าจอจะแสดงที่อยู่ เช่น https://192.168.1.20:8443 และรหัสจับคู่
  2. บนคอมพิวเตอร์เครื่องเดียวกัน เปิด https://localhost:8443/store.html เลื่อนไปที่ “เชื่อมหลายเครื่อง” แล้วเลือก “เครื่องหลัก (รวมยอด)” จะเห็นรหัสจับคู่และปุ่มคัดลอกลิงก์จับคู่
  3. บนมือถือแต่ละเครื่อง เปิด https://192.168.1.20:8443/store.html (ใช้ IP ของเครื่องหลัก) เลือก “เครื่องลูก (จุดนับ)” ตั้งชื่อจุด ใส่รหัสจับคู่ แล้วกด “จับคู่” หรือเปิดลิงก์จับคู่ที่ส่งมาจากเครื่องหลัก
  4. บนมือถือ กด “เปิดกล้อง” วาดเส้นนับ/โซนตามปกติ เครื่องจะส่งยอดให้เครื่องหลักทุก 15 วินาที ถ้าเน็ตหลุดจะเก็บไว้แล้วส่งให้เองเมื่อเชื่อมต่อได้

มือถือส่งเฉพาะตัวเลขสรุปรายวัน (จำนวนเข้า–ออก รายชั่วโมง โซน คิว และชื่อจุด) ไม่ส่งภาพ วิดีโอ หรือฮีตแมป เซิร์ฟเวอร์รับเฉพาะเครื่องในวง LAN ที่จับคู่แล้ว เครื่องหลักลบเครื่องลูกหรือเปลี่ยนรหัสได้ตลอด ยอดรวมจะแสดงในหน้า “วิเคราะห์หน้าร้าน” และ “แดชบอร์ดรวม” ของเครื่องหลัก บนเว็บสาธิต (GitHub Pages) ไม่มีเซิร์ฟเวอร์กลาง ให้ใช้ “ส่งต่อด้วยไฟล์” แทน

ชุดค่าการติดตั้ง: โหมดลูกค้า หรือ เดโมงานวิจัย

ทุกเว็บ รวมเว็บสาธิตบน GitHub Pages เปิดในโหมดลูกค้าเป็นค่าเริ่มต้น (LENSIQ_PROFILE = "commercial") ซึ่งไม่โหลดและไม่แสดงโมเดลอายุ/เพศ (UTKFace) และโมเดลสีหน้า ส่วนโมเดลแยกส่วนใบหน้า BiSeNet ปิดอยู่ (LENSIQ_FACEPARSE = false และไม่มีไฟล์โมเดลในชุดไฟล์ของเว็บ) สวิตช์ "เดโมงานวิจัย" ด้านล่างเปิดโมเดลอายุ/เพศและสีหน้ากลับมาเฉพาะในเครื่องนี้เพื่อสาธิตหรือวิจัย (ปิดไว้เป็นค่าเริ่มต้น ปิดกลับได้ตลอด) ถ้าเปิดไว้บนเว็บที่ไม่ใช่เว็บสาธิต หน้ากล้องจะมีแถบเตือนสีแดง

ผู้ติดตั้งล็อกโหมดลูกค้าให้ทุกเครื่องได้ด้วย window.LENSIQ_RESEARCH_DEMO = false ใน lensiq-config.js (การติดตั้งให้ลูกค้า: สวิตช์จะเปิดไม่ได้) · เครื่องสาธิตตั้ง window.LENSIQ_PROFILE = "demo" ได้ · โมเดลตรวจจับ/จดจำใบหน้าของ face-api.js ยังรอความเห็นทนายความ (F5/F6) ป้าย "โมเดลใบอนุญาตวิจัย" จึงยังแสดงในทั้งสองโหมด

ใช้กล้อง IP / กล้องวงจรปิด (ผ่านโปรแกรมเว็บแคมเสมือน)

หน้าเว็บเปิดได้เฉพาะกล้องที่เบราว์เซอร์มองเห็น (เว็บแคม กล้อง USB กล้องมือถือ) ระบบยังไม่รับสัญญาณ RTSP หรือ ONVIF โดยตรง วิธีใช้กล้อง IP คือให้คอมพิวเตอร์หน้างานแปลงภาพจากกล้อง IP เป็นเว็บแคมเสมือน แล้วเลือกกล้องนั้นในหน้าเว็บตามปกติ

วิธีที่ 1: OBS Studio (Windows / macOS / Linux)

  1. ติดตั้ง OBS Studio (ฟรี โอเพนซอร์ส) บนคอมพิวเตอร์ที่อยู่ในเครือข่ายเดียวกับกล้อง
  2. ใน OBS กด + ที่ “แหล่งที่มา” เลือก “แหล่งสื่อ (Media Source)” เอาเครื่องหมายถูก “ไฟล์ในเครื่อง” ออก แล้วใส่ที่อยู่ RTSP ของกล้อง เช่น rtsp://user:pass@192.168.1.64:554/stream1 (ดูรูปแบบที่อยู่ในคู่มือกล้อง)
  3. กด “เริ่มกล้องเสมือน (Start Virtual Camera)” ที่มุมขวาล่างของ OBS
  4. เปิดหน้าระบบในเบราว์เซอร์บนเครื่องเดียวกัน อนุญาตกล้อง แล้วเลือก “OBS Virtual Camera” ในรายการกล้อง

วิธีที่ 2: go2rtc (เครื่องที่เปิดทิ้งไว้ หรือหลายกล้อง)

  1. ติดตั้ง go2rtc (โอเพนซอร์ส MIT) แล้วเพิ่มกล้องในไฟล์ตั้งค่า เช่น streams: { door: rtsp://user:pass@192.168.1.64:554/stream1 }
  2. เปิดหน้าเว็บของ go2rtc ตรวจว่าเห็นภาพ แล้วส่งภาพนั้นเข้าเว็บแคมเสมือน (OBS Virtual Camera หรือ v4l2loopback บน Linux)
  3. เลือกเว็บแคมเสมือนนั้นในหน้าระบบ เหมือนวิธีที่ 1

ข้อควรรู้: ภาพผ่านโปรแกรมเพิ่มความหน่วงราว 0.2–1 วินาที ซึ่งพอสำหรับนับคนและตรวจคุณภาพ แต่ไม่ควรใช้กับระบบเตือนคนขับ · ใช้สตรีมความละเอียดรอง (เช่น 640×480 หรือ 1280×720) เพื่อลดภาระเครื่อง · รหัสผ่านกล้องอยู่ในเครื่องหน้างานเท่านั้น หน้าเว็บไม่เห็นและไม่ส่งออก · ภาพยังประมวลผลในเบราว์เซอร์บนเครื่องนั้นเหมือนเว็บแคมทั่วไป

LENSIQ ไม่ได้รวมหรือติดตั้งโปรแกรมเหล่านี้ให้ และยังไม่ได้ทดสอบกล้อง IP ทุกยี่ห้อ ให้ทดลองกับกล้องของคุณ แล้วใช้ “ตรวจความแม่นยำหน้างาน” ในหน้าระบบก่อนใช้ตัวเลขจริง

ข้อควรรู้ด้าน PDPA: ระบบที่วิเคราะห์ใบหน้าหรือพฤติกรรมคนต้องติดป้ายแจ้งและขอความยินยอมตามกฎหมาย ระบบในหน้านี้ออกแบบให้ไม่บันทึกภาพคนและเก็บเพียงสถิติไว้ในเครื่อง ผลการประเมินเพศ อายุ และอารมณ์เป็นการคาดคะเนที่อาจคลาดเคลื่อน ดู ความแม่นยำที่วัดได้
