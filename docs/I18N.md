# LENSIQ i18n — Thai (default), English and Simplified Chinese

Every page shows a **TH | EN | 中文** switch in the header. The switch, the menu and the shared footer strings already
work on all pages. To translate a page you add `data-i18n` attributes and a page dictionary. You do not need a new
`<script>` tag.

## How it loads

| File | Loaded by | What it does |
|---|---|---|
| `lensiq-i18n.js` | `nav.js` (it injects the script if the page does not include it) | `window.LQI18N` core: dictionaries, `t()`, applies `data-i18n`, persists the language |
| `i18n/zh-common.js` | `nav.js` | Chinese for the nav, footer, common buttons, model notice, face-vault states, PDPA texts and `index.html` |
| `i18n/zh-<page>.js` | your page (one `<script>` tag, anywhere) | Chinese for one page |

`nav.js` inserts the two scripts with `async = false`, so they run in order but **after** the parser-blocking scripts
that follow `nav.js` in the page. The design copes with that:

- Thai is the default and lives in your HTML and JS, so nothing waits for i18n.
- Dictionaries use a queue (`window.LQI18N_Q`). They work whether they load before or after the core.
- When the stored language is Chinese, the core applies it once the DOM is ready. It then fires the `lq-lang`
  event, and your page re-renders its dynamic text then.

If your page script needs `LQI18N` at parse time, add `<script src="lensiq-i18n.js"></script>` before it. `nav.js`
detects the tag and does not inject a second copy.

## Static markup

```html
<h2 data-i18n="store.title">วิเคราะห์หน้าร้าน</h2>                <!-- key; the Thai in the markup is the default -->
<button data-i18n>เริ่ม</button>                                   <!-- empty value: the Thai text itself is the key -->
<input data-i18n-attr="placeholder:store.search.ph;aria-label:store.search" placeholder="ค้นหา" aria-label="ค้นหา">
<a class="btn" href="x.html"><span data-i18n="store.cta">เปิดกล้อง</span><svg>…</svg></a>
```

Rules:

- **Thai is never duplicated in a dictionary.** The markup's own text is remembered and restored when someone
  switches back to Thai. A rename in the HTML therefore needs no dictionary change, but the Chinese entry should be
  updated too.
- If an element has child elements, only its **first non-empty direct text node** is replaced, so icons survive.
  For mixed text, wrap each piece in its own `<span data-i18n>` (see the hero `<h1>` in `index.html`).
- Text is always set as text, never as HTML. Attributes are limited to text attributes: `on*`, `href` and `src`
  are refused.
- Elements added later (rendered lists, dialogs) are translated automatically while Chinese is active, through a
  MutationObserver.
- **Text that your JS rewrites** (counters, status lines) should not use `data-i18n`. Use `t()` (see below), because
  the remembered Thai original would be stale.
- Keys for an `<option>` change its text. Always give options an explicit `value` so the stored data does not change
  with the language.

## Dynamic text (JS)

```js
const T = (key, thai, vars) => window.LQI18N ? LQI18N.tf(key, thai, vars) : thai.replace(/\{(\w+)\}/g, (m, k) => vars?.[k] ?? m);
el.textContent = T("store.count", "มี {n} คนในร้าน", { n });
window.addEventListener("lq-lang", () => render());        // re-render on every switch (and once at start-up)
```

The API:

- `LQI18N.t(key, vars?, lang?)` looks up the current language first, then Thai, then the key itself.
  `{name}` placeholders are filled from `vars`.
- `LQI18N.tf(key, thaiDefault, vars?)` does the same lookup, but uses your Thai default when the key is unknown.
  This is the recommended call from page code.
- `LQI18N.lang` reads the current language (`"th"` or `"zh"`). Set it to switch, or call
  `LQI18N.setLang("zh")`.
- `LQI18N.apply(root?)` re-translates the `data-i18n` elements under `root`.
- `LQI18N.add({ zh: {...} })` adds entries; `LQI18N.add("zh", {...})` does the same for one language.
- The `lq-lang` event on `window` carries `detail` `{ lang, prev, init }`.

Other behaviour:

- The language persists in localStorage under `lq-lang`. `?lang=zh` or `?lang=th` in the URL overrides it and is
  saved too.
- `<html lang>` becomes `th` or `zh-Hans`. CSS can target `html[lang^=zh]` (the Chinese font stack is in
  `styles.css`).
- Canvas text has to be redrawn with `t()`/`tf()`. `home.js` redraws every frame, so its labels follow the language.

## Page dictionary: `i18n/zh-<page>.js`

```js
/* i18n/zh-store.js — Simplified Chinese for store.html (Thai lives in the markup / store.js). */
(window.LQI18N_Q = window.LQI18N_Q || []).push({ zh: {
  "store.title": "门店分析",
  "store.count": "店内有 {n} 人",
  "เริ่ม": "开始"
} });
```

Add `<script src="i18n/zh-store.js"></script>` to `store.html`, anywhere in the page. Prefix your keys with the page
name (`store.*`).

Before writing your own entries, reuse the common ones in `i18n/zh-common.js`:

- `nav.<page>.title` / `nav.<page>.desc` for page names, which match the menu
- `foot.*` for the footer
- Thai-text keys for common buttons: `"เริ่ม"`, `"หยุด"`, `"ถ่ายรูป"`, `"ดาวน์โหลด"`, `"ลบข้อมูลทั้งหมด"` …
- `pdpa.*` for consent texts and `vault.*` for face-data states

Menu keys come from the page file name: `nav.faceread.title` is the entry for `faceread.html`. When the Thai menu
title in `nav.js` changes (for example when the fortune pages drop the word "AI"), the key stays the same.
`tests/unit/i18n.test.js` fails if any menu entry lacks a Chinese title or description.

## Thai line breaking (related)

`nav.js` wraps Thai words in `<span class="lq-run">` and `<span class="lq-w">` (nowrap), with `<wbr>` between words.
It does this for every word in headings, labels and buttons, and for known loanwords elsewhere ("แดชบอร์ด"), which
the browser's dictionary would otherwise split mid-syllable. `textContent` is unchanged. Two cases need care:

- If your code walks child nodes of such elements, read `textContent` instead.
- To opt a block in, add the class `lq-wb`. To keep an element out of the rewrite, put it inside `pre`, `code` or
  `[contenteditable]`.
- To add a loanword, edit the `JOIN` list in `nav.js` and in `tools/mobile-audit.mjs`.

## Measuring coverage (how much Thai is left in 中文 mode)

- **In the browser:** add `?i18n=debug` to any page, or set `localStorage["lq-i18n-debug"] = "1"`. In 中文 mode every
  element that still shows Thai gets a red dashed outline. A badge in the bottom-left corner shows the live Thai %, the
  number of nodes and the number of *mixed* nodes (Thai and Chinese in the same text). Click the badge to print the list
  with CSS paths (`console.table`). The badge updates as the page changes, so you can open dialogs and results and
  watch it.
- **Headless, all pages:** `node tools/zh-coverage.mjs` (or `npm run zh:coverage`). It loads every page at 390 px in
  中文, measures, then runs the typical interactions and measures again: open `<details>`, click tabs, run your own
  clicks from `tools/zh-coverage.interactions.json`, and open the mobile menu. A page's score is its worst state.
  Useful flags:
  - `--top 20 tarot` lists the 20 biggest leftovers with their CSS paths.
  - `--max 5` exits 1 above 5 %.
  - `--json out.json` writes the result as JSON.
  - `--desktop` uses a 1280 px viewport.
- **Shared components gate (CI):** `node tools/zh-coverage.mjs --shared --no-interact --max 0`. It covers the header
  (including the closed menus), footer, model notice and consent boxes, with hidden text counted. All must be 100 %
  Chinese.
- **What counts:** visible text, the `placeholder`/`title`/`aria-label`/`alt` attributes and `<title>`. Score =
  Thai letters ÷ (Thai + Chinese letters). Canvas text is not measured. Content that must stay Thai, such as Thai
  sample data, a person's name or a Thai-language example, should be marked `lang="th"` (semantically correct) or
  `translate="no"`, and is then excluded.
- **API:** `LQI18N.coverage(root?, { top, all })` returns `{ thai, cjk, pct, nodes, mixed, attrs, top: [{ text, path, thai, mixed }] }`.

## Tests

- `tests/unit/i18n.test.js` covers the core API, persistence, the queue, nav and index key coverage, and that
  placeholders match.
- `tests/e2e/i18n.e2e.mjs` runs on `index.html` and `fortune.html` at 390 and 1280 px, and checks `coverage()` and the debug overlay on `index.html` and `about.html`. It checks the switch to 中文
  and back (Thai restored exactly), persistence, no horizontal overflow and no exceptions.
- `node tools/mobile-audit.mjs --lang zh` gives a phone layout report in Chinese.


## English (`en`)

- `lq-lang` = `th` | `en` | `zh`; `<html lang>` becomes `th`, `en` or `zh-Hans`; `?lang=en` works like `?lang=zh`.
- English dictionaries mirror the Chinese ones key for key: `i18n/en-<name>.js` next to every `i18n/zh-<name>.js`
  (page dictionaries push `{ en: {...} }`; run-time dictionaries push `{ "@lang": "en", "ไทย": "English" }`).
- **No extra `<script>` tags.** When English is chosen, `lensiq-i18n.js` injects `i18n/en-X.js` for every
  `<script src="i18n/zh-X.js">` on the page (including `zh-kb-*` → `en-kb-*`, the English reading data), waits for them,
  then applies English and fires `lq-lang` (with `init: false`, so pages re-render). Thai/Chinese visitors download nothing extra.
- `lensiq-i18n-rt.js` keeps one dictionary per language. Options (`window.LQI18N_RT_CFG` or `LQI18N_RTX.config()`):
  `langs`, `exactOnly` (whole strings / templates / dates only), `skip` (CSS selector left untouched).
- Fortune pages: readings are composed natively in all three languages by `fortune-ai.js` `compose()` (the language
  comes from `opts.lang` or `LQI18N.lang`). English mirrors Chinese: `composeEn()` reads `i18n/en-kb-<domain>.js`
  (`window.FORTUNE_EN_Q` / `FORTUNE_EN`, the same concept keys as `zh-kb-*`, mapped by `zhKeys()`), never translates the
  Thai text and skips any item without English data. A domain with no English data at all falls back to the Thai reading,
  and only then does `i18n/en-fortune.js` show its "readings are in Thai or Chinese" note.
  - **Field grammar** (`en-kb-*`): `n` name as it reads mid-sentence ("the Fool card (upright)", "your Sun in Aries"),
    `s` short name, `o p w m l c t` complete lowercase clauses addressed to "you" with no final period, `a` an
    imperative verb phrase ("take the first step …", or "when …, …"), optional `x` a one-clause gloss that explains a
    Thai/Chinese concept (Taksa bhumi, BaZi Day Master, Lek 7 Tua 9 Than, kua number, siam si …) the first time the item
    is named (glosses that open the same way are shown once; at most three per reading). Digits only in `n`/`s`.
  - The result has the same shape as Thai/Chinese: sections, polarity (caution items get a gentle lead and a practical
    step in the same unit), `summary`, `plan` ("Your three-step plan", English `REMEDY_EN`) and `reminder` (Kalama
    Sutta: traditional texts and beliefs, use your own judgement, everything can change through your own actions).
  - `FA.lint()` runs `lintEn()` for English results: no Thai/Chinese, safety (`UNSAFE_EN_CAT`: the same categories as
    Thai/Chinese), sentence case, punctuation, duplicates, doubled words, repeated subject, `label-echo`, `report-chain`,
    `that-clause`, filler budget, plus the shared `advice-topic`, `caution-gentle`, `remedy-safety` and `remedy-match`.
    `FA.lintSemantic()` checks number evidence, omen wording for reflective dreams, section fit and zodiac-pair person.
  - **The writing assistant (Claude) is not used in English or Chinese** — `interpret()` composes locally, because the
    grounding gate (`groundAI`) that vets assistant sentences against the knowledge bases works on Thai text only.
  - Share cards use `FortuneAI.en.keyLines(result)` for English results.
  - Tests: `tests/unit/fortune-en.test.js` (all 16 domains × seeds × topics), `tests/e2e/fortune-en.e2e.mjs` (every page).
- Parity check (keys, placeholders, no Thai/CJK, no "AI" in values) — compare each `en-X.js` with `zh-X.js` before
  shipping. Coverage gate: `npm run en:coverage` (`node tools/zh-coverage.mjs --lang en`), `npm run en:shared`.
- Wording: no "AI" in labels, titles, menus or buttons in any language. The optional writing assistant is named with
  its provider wherever data leaves the device: "ผู้ช่วยเขียนคำทำนาย (Claude โดย Anthropic)" /
  "writing assistant (Claude by Anthropic, USA)" / "写作助手（Anthropic 的 Claude，美国）".
