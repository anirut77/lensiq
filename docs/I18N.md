# LENSIQ i18n — Thai (default) and Simplified Chinese

Every page shows a **TH | 中文** switch in the header. The switch, the menu and the shared footer strings already
work on all pages. To translate a page you add `data-i18n` attributes and a page dictionary. You do not need a new
`<script>` tag.

## How it loads

| File | Loaded by | What it does |
|---|---|---|
| `lensiq-i18n.js` | `nav.js` (it injects the script if the page does not include it) | `window.LQI18N` core: dictionaries, `t()`, applies `data-i18n`, persists the language |
| `i18n/zh-common.js` | `nav.js` | Chinese for the nav, footer, common buttons, model notice, face-vault states, PDPA texts and `index.html` |
| `i18n/zh-<page>.js` | your page (one `<script>` tag, anywhere) | Chinese for one page |

`nav.js` inserts the two scripts with `async = false`, so they run in order but **after** the parser-blocking scripts
that follow `nav.js` in the page. The design copes with that:

- Thai is the default and lives in your HTML and JS, so nothing waits for i18n.
- Dictionaries use a queue (`window.LQI18N_Q`). They work whether they load before or after the core.
- When the stored language is Chinese, the core applies it once the DOM is ready. It then fires the `lq-lang`
  event, and your page re-renders its dynamic text then.

If your page script needs `LQI18N` at parse time, add `<script src="lensiq-i18n.js"></script>` before it. `nav.js`
detects the tag and does not inject a second copy.

## Static markup

```html
<h2 data-i18n="store.title">วิเคราะห์หน้าร้าน</h2>                <!-- key; the Thai in the markup is the default -->
<button data-i18n>เริ่ม</button>                                   <!-- empty value: the Thai text itself is the key -->
<input data-i18n-attr="placeholder:store.search.ph;aria-label:store.search" placeholder="ค้นหา" aria-label="ค้นหา">
<a class="btn" href="x.html"><span data-i18n="store.cta">เปิดกล้อง</span><svg>…</svg></a>
```

Rules:

- **Thai is never duplicated in a dictionary.** The markup's own text is remembered and restored when someone
  switches back to Thai. A rename in the HTML therefore needs no dictionary change, but the Chinese entry should be
  updated too.
- If an element has child elements, only its **first non-empty direct text node** is replaced, so icons survive.
  For mixed text, wrap each piece in its own `<span data-i18n>` (see the hero `<h1>` in `index.html`).
- Text is always set as text, never as HTML. Attributes are limited to text attributes: `on*`, `href` and `src`
  are refused.
- Elements added later (rendered lists, dialogs) are translated automatically while Chinese is active, through a
  MutationObserver.
- **Text that your JS rewrites** (counters, status lines) should not use `data-i18n`. Use `t()` (see below), because
  the remembered Thai original would be stale.
- Keys for an `<option>` change its text. Always give options an explicit `value` so the stored data does not change
  with the language.

## Dynamic text (JS)

```js
const T = (key, thai, vars) => window.LQI18N ? LQI18N.tf(key, thai, vars) : thai.replace(/\{(\w+)\}/g, (m, k) => vars?.[k] ?? m);
el.textContent = T("store.count", "มี {n} คนในร้าน", { n });
window.addEventListener("lq-lang", () => render());        // re-render on every switch (and once at start-up)
```

The API:

- `LQI18N.t(key, vars?, lang?)` looks up the current language first, then Thai, then the key itself.
  `{name}` placeholders are filled from `vars`.
- `LQI18N.tf(key, thaiDefault, vars?)` does the same lookup, but uses your Thai default when the key is unknown.
  This is the recommended call from page code.
- `LQI18N.lang` reads the current language (`"th"` or `"zh"`). Set it to switch, or call
  `LQI18N.setLang("zh")`.
- `LQI18N.apply(root?)` re-translates the `data-i18n` elements under `root`.
- `LQI18N.add({ zh: {...} })` adds entries; `LQI18N.add("zh", {...})` does the same for one language.
- The `lq-lang` event on `window` carries `detail` `{ lang, prev, init }`.

Other behaviour:

- The language persists in localStorage under `lq-lang`. `?lang=zh` or `?lang=th` in the URL overrides it and is
  saved too.
- `<html lang>` becomes `th` or `zh-Hans`. CSS can target `html[lang^=zh]` (the Chinese font stack is in
  `styles.css`).
- Canvas text has to be redrawn with `t()`/`tf()`. `home.js` redraws every frame, so its labels follow the language.

## Page dictionary: `i18n/zh-<page>.js`

```js
/* i18n/zh-store.js — Simplified Chinese for store.html (Thai lives in the markup / store.js). */
(window.LQI18N_Q = window.LQI18N_Q || []).push({ zh: {
  "store.title": "门店分析",
  "store.count": "店内有 {n} 人",
  "เริ่ม": "开始"
} });
```

Add `<script src="i18n/zh-store.js"></script>` to `store.html`, anywhere in the page. Prefix your keys with the page
name (`store.*`).

Before writing your own entries, reuse the common ones in `i18n/zh-common.js`:

- `nav.<page>.title` / `nav.<page>.desc` for page names, which match the menu
- `foot.*` for the footer
- Thai-text keys for common buttons: `"เริ่ม"`, `"หยุด"`, `"ถ่ายรูป"`, `"ดาวน์โหลด"`, `"ลบข้อมูลทั้งหมด"` …
- `pdpa.*` for consent texts and `vault.*` for face-data states

Menu keys come from the page file name: `nav.faceread.title` is the entry for `faceread.html`. When the Thai menu
title in `nav.js` changes (for example when the fortune pages drop the word "AI"), the key stays the same.
`tests/unit/i18n.test.js` fails if any menu entry lacks a Chinese title or description.

## Thai line breaking (related)

`nav.js` wraps Thai words in `<span class="lq-run">` and `<span class="lq-w">` (nowrap), with `<wbr>` between words.
It does this for every word in headings, labels and buttons, and for known loanwords elsewhere ("แดชบอร์ด"), which
the browser's dictionary would otherwise split mid-syllable. `textContent` is unchanged. Two cases need care:

- If your code walks child nodes of such elements, read `textContent` instead.
- To opt a block in, add the class `lq-wb`. To keep an element out of the rewrite, put it inside `pre`, `code` or
  `[contenteditable]`.
- To add a loanword, edit the `JOIN` list in `nav.js` and in `tools/mobile-audit.mjs`.

## Tests

- `tests/unit/i18n.test.js` covers the core API, persistence, the queue, nav and index key coverage, and that
  placeholders match.
- `tests/e2e/i18n.e2e.mjs` runs on `index.html` and `fortune.html` at 390 and 1280 px. It checks the switch to 中文
  and back (Thai restored exactly), persistence, no horizontal overflow and no exceptions.
