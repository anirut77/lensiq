## 2. กฎให้คะแนนที่ล็อกไว้ (`seatwatch-score-v1`)

ล็อกก่อนเขียนเครื่องมือ: `tests/unit/hall-seatwatch-score.test.js` (sha256 ใน `evals-locks/gate-hall-h.sha256`) ห้ามแก้หลังเปิดผลช่วงตัดสิน (held-out)
ช่วงแรก ถ้าจำเป็นต้องแก้ = รุ่นกฎใหม่ + รอบตัดสินใหม่

1. **เวลา:** ทุกเวลาแปลงเป็น "นาฬิกากลางห้อง" (วินาทีนับจาก 00:00 ของช่วง) ด้วยค่าที่จดตอนเริ่มและตอนจบช่วง (เวลาเครื่อง ↔ เวลานาฬิกากลาง) แก้นาฬิกาเครื่องเดินเร็ว/ช้าแบบเส้นตรง
2. **แถวในแผ่นบันทึก:** `on_time` = Y → เริ่มตามบท, จบ = `actual_end` หรือ เริ่ม + ความยาวตามบท (ลุก 70 · ทางเดิน 25 · คนที่สอง 30 · เอน 20 · ยืน 12 · โทรศัพท์ 20 · ผู้คุมเดิน 30 · อื่น 15 วินาที) ·
   N / นอกบท → ใช้เวลาจริง (ต้องกรอก) · X → ตัดทิ้ง · `LEAVE` ต้องมีเวลากลับเสมอ
3. **เหตุการณ์ → สัญญาณที่ควรแจ้ง:** `LEAVE` → `empty` (ที่นั่งนั้น) + `back` (นับจากเวลากลับ) + `early` (เฉพาะครั้งแรกของที่นั่งในรอบ ไม่อยู่ ≥ 180 วินาที และยังอยู่ในเวลาห้ามออก) ·
   `AISLE` และ `STAFF_WALK` ที่ปิดโหมดเดินตรวจ → `aisle` (ทั้งห้อง) · `SECOND` → `extra` ที่ **ที่นั่งที่ถูกไปยืนข้าง** (`target_seat`) · `LEAN` → `lean` ที่ที่นั่งของคนที่เอน ·
   `PHONE_*` → `phone` เฉพาะช่วงที่เปิดสัญญาณโทรศัพท์ · `STAND` / `DISTRACT` / `OTHER` / `STAFF_WALK` ที่เปิดโหมดเดินตรวจ → ไม่มีสัญญาณที่ควรแจ้ง
4. **นับได้ (scoreable) / สีเทา (grey):** ลุก ≥ 35 วินาที · ทางเดิน ≥ 23 · คนที่สอง ≥ 20 · เอน ≥ 19 · โทรศัพท์ ≥ 15 · `early` ต้องไม่อยู่ ≥ 195 วินาที
   สั้นกว่านี้ = **สีเทา**: ไม่นับเป็นพลาด และการแจ้งตรงเหตุการณ์นั้นไม่นับเป็นแจ้งผิด
   **ช่วงพัก (cooldown):** ถ้ามีการแจ้งสัญญาณเดียวกันที่ที่นั่งเดียวกัน (ทางเดิน: ทั้งห้อง) ภายใน 95 วินาทีก่อนเหตุการณ์ → เหตุการณ์นั้นเป็นสีเทา (ระบบตั้งใจเงียบ)
5. **จับคู่:** การแจ้งที่สัญญาณเดียวกัน ที่นั่งเดียวกัน เวลาอยู่ระหว่าง **5 วินาทีก่อนเริ่ม ถึง H + 15 วินาทีหลังเริ่ม**
   (H: ว่าง 20 · กลับ 2 นับจากเวลากลับ · ออกก่อนเวลา 180 · คนที่สอง 5 · ทางเดิน 8 · เอน 4 · โทรศัพท์ 2 วินาที)
   หนึ่งการแจ้งจับคู่ได้หนึ่งเหตุการณ์ เหตุการณ์เรียงตามเวลา จับกับการแจ้งที่เร็วที่สุดในช่วง
6. **ช้า (late):** สัญญาณและที่นั่งถูก แต่หลังช่วงจับคู่ขณะเหตุการณ์ยังเกิดอยู่ = นับเป็น**พลาด**สำหรับ recall แต่**ไม่ใช่**แจ้งผิด รายงานแยก
7. **ซ้ำ (repeat):** การแจ้งครั้งถัดไปของข้อเท็จจริงที่ยังเป็นจริงอยู่ (เช่นระดับ "ไปตรวจ" ของคนที่สอง) = ไม่ถูกไม่ผิด นับแยก
8. **แจ้งผิด:** การแจ้ง `empty` `back` `early` `extra` `aisle` `lean` (และ `phone` เมื่อเปิด) ที่ไม่ตรงข้อใดข้างบน ·
   ที่นั่งผิด = แจ้งผิดที่ที่นั่งที่แสดง **และ** พลาดที่ที่นั่งจริง · ภายใน 300 วินาทีหลังกล้องถูกขยับ (`CAM_MOVED`) = นับแยก ไม่อยู่ในอัตราหลัก ·
   `room` `roommute` `setup` = ไม่ใช่การแจ้ง นับแยก
9. **สาเหตุของการแจ้งผิด:** เครื่องมือเสนอ (ผู้คุมเดิน → `staff`, ยืน → `standing`, ท่าทางอื่น → `posture`) ผู้ควบคุมเครื่องกับผู้สังเกตยืนยันใน `causes.csv`
   (`alert_id,cause,note` สาเหตุจากรายการ: person-missed · object · standing · wrong-seat · staff · posture · light · camera-moved · unknown หรือ `unsure`)
   **ไม่แน่ใจ (unsure)** ไม่อยู่ในบรรทัดหลัก แต่นับเป็นแจ้งผิดในบรรทัด "กรณีเลวร้ายที่สุด"
10. **ตัวชี้วัดและเป้า (§7 ของ protocol):** recall + Wilson 95 % · ความแม่น · แจ้งผิดต่อที่นั่ง-ชั่วโมง + Poisson 95 % แบบ exact ·
    T1 ว่าง/กลับ/ทางเดิน ขอบล่าง ≥ 80 % · T2 คนที่สอง/เอน ขอบล่าง ≥ 70 % · ต่ำกว่า 55 เหตุการณ์ที่นับได้ = "เหตุการณ์ไม่พอ" ·
    T4 แจ้งผิด ≤ 3 ต่อการสอบ 30 ที่นั่ง 3 ชม. (ระดับเฝ้าดู/ไปตรวจ ≤ 1) **ตัดสินเฉพาะแบบ A (30 ที่นั่ง)** · T5 เวลาแจ้ง มัธยฐาน ≤ H + 5, p90 ≤ H + 10 ·
    T6 ความคลาดเวลาที่ไม่อยู่ มัธยฐาน ≤ 10 วินาที · T7 ≥ 2 รอบตรวจต่อวินาที · ช่วงซ้อม (dev) กับช่วงตัดสิน (held-out) รายงานแยกเสมอ
11. **ที่นั่ง-ชั่วโมง** = จำนวนที่นั่งที่วาดและมีอาสาสมัคร × เวลาเฝ้าดูของช่วง

## 3. เตรียมไฟล์ (ทั้งหมดอยู่นอก repo เช่น `~/LENSIQ-field/evals/exam-seatwatch/<รหัสรอบ>/`)

```
labels.csv            แผ่นบันทึกของผู้สังเกตที่พิมพ์ลง CSV (แม่แบบ docs/pilot/label-sheet-template.csv)
H1-cam1.json ...      ไฟล์เหตุการณ์ของแต่ละเครื่องกล้องแต่ละช่วง (exam-hall.html → "ส่งออกเหตุการณ์")
seats-cam1.json       ผังที่นั่ง (exam-hall.html → "ส่งออกผังที่นั่ง")
session.json          บันทึกรอบ (แม่แบบ docs/pilot/seatwatch-session-template.json)
causes.csv            (หลังตรวจข้อขัดแย้งตาม §13 ของ protocol) สาเหตุของการแจ้งผิดแต่ละครั้ง
```

`session.json` (หนึ่งไฟล์ต่อรอบ / ต่อกล้อง): `split` = `dev` หรือ `heldout` · `variant` = `A` หรือ `B` · แต่ละช่วงมี `block` (ตรงกับคอลัมน์ block ในแผ่น),
`log` (ไฟล์เหตุการณ์), `seats` (หมายเลขที่นั่งที่มีคนนั่ง), `minLeaveMin`, `monitoredSec`, `clock` (ค่าที่จดตอนเริ่ม/จบช่วง), `fps` (รอบตรวจต่อวินาทีที่จดต้น/กลาง/ท้าย),
`node` (ถ้าไฟล์เหตุการณ์มีหลายเครื่อง) และข้อมูลแสง/ตำแหน่งกล้อง/ผลตรวจตำแหน่งกล้อง

## 4. รัน

```sh
# รอบสด (ค่าเริ่มต้น ไม่บันทึกวิดีโอ)
node tools/hall-seatwatch-score.mjs --session ~/LENSIQ-field/evals/exam-seatwatch/S1/session.json --out ~/LENSIQ-field/evals/exam-seatwatch/S1/result
# หลังตรวจข้อขัดแย้งแล้ว: ใส่สาเหตุ
node tools/hall-seatwatch-score.mjs --session …/session.json --causes …/causes.csv --out …/result
# รอบที่มีวิดีโอ + ทุกคนยินยอมแบบ ข.: สร้างไฟล์เหตุการณ์จากวิดีโอ (ตัวตรวจ COCO-SSD และ YOLOX-Nano บนเหตุการณ์ชุดเดียวกัน)
node tools/hall-seatwatch-replay.mjs --video …/H1.mp4 --seats …/seats-cam1.json --start-timer 00:00 --labels …/labels.csv --block H1 --out …/H1-coco.json
node tools/hall-seatwatch-replay.mjs --video …/H1.mp4 --seats …/seats-cam1.json --start-timer 00:00 --labels …/labels.csv --block H1 --detector yolox --out …/H1-yolox.json
```

`--start-timer` = เวลาที่นาฬิกากลางห้องแสดงในภาพแรกของวิดีโอ (ให้นาฬิกาอยู่ในภาพ) · ไฟล์เล่นซ้ำใช้เวลานาฬิกากลางห้องโดยตรง จึงไม่ต้องใส่ `clock`
ข้อจำกัด: เล่นที่จำนวนภาพต่อวินาทีคงที่ (ค่าเริ่มต้น 3) หน้าเว็บจริงทำ 2–5 รอบต่อวินาทีไม่คงที่ ผลจากวิดีโอจึงติดป้าย "replay" แยกจากผลสด
ภาพที่แยกจากวิดีโอเก็บในโฟลเดอร์ชั่วคราวและลบทันทีเมื่อจบ วิดีโอต้องลบตามวันที่เขียนในใบยินยอม (ข้อเสนอ ≤ 14 วัน) และจดวันลบในบันทึกรอบ

## 5. แผ่นสรุปผล (`RESULT-SHEET.md` ที่เครื่องมือเขียน)

หัวแผ่นมีที่มาเสมอ: **"ที่มา: หน้างานจริง (สอบจำลอง อาสาสมัครผู้ใหญ่ ทำตามบท)"** และรุ่นกฎ ตามด้วยสองตาราง (ช่วงซ้อม / ช่วงตัดสิน แยกกัน):

| Signal | Scoreable events | Found | Recall | Wilson 95 % | Target | Pass? | Late | Median / p90 time to alert | False alerts | Repeats | Grey hits |
|---|---|---|---|---|---|---|---|---|---|---|---|

| False alerts | Count | Seat-hours | Per seat-hour | Poisson 95 % | Per 30-seat 3-h exam | Target | Unsure (worst case) |
|---|---|---|---|---|---|---|---|

ตามด้วยสาเหตุ การแจ้งช่วงกล้องถูกขยับ สิ่งที่ไม่ใช่การแจ้ง T5–T7 · `events.csv` (ทุกเหตุการณ์ที่ควรแจ้ง: นับได้/เทา/เจอ/ช้า) และ `alerts.csv`
(ทุกการแจ้ง: ถูก/ช้า/ซ้ำ/ผิด/กล้องถูกขยับ/ไม่ใช่การแจ้ง) ใช้ให้**ผู้ตรวจอิสระ**คำนวณซ้ำก่อนส่งเจ้าของ (กฎทุกรอบ)
ผลที่ส่งเข้าเอกสารขายหรือหน้าเว็บได้: เฉพาะช่วงตัดสิน แสง ตำแหน่งกล้อง และขนาดห้องที่วัดจริง ห้ามพูดถึง "การโกง" ห้ามอ้างกับผู้เยาว์ ห้ามคำว่า "สอบจริง"

## 6. ความเป็นส่วนตัว

ไม่มีชื่อในไฟล์ใด ใช้หมายเลขที่นั่ง · ไฟล์ทั้งหมดอยู่นอก repo (เครื่องมือไม่ยอมเขียนผลหรืออ่านวิดีโอใน repo) · ไม่ประมวลผลใบหน้า ไม่ประเมินอารมณ์หรือพฤติกรรม ·
วิดีโอมีได้เฉพาะเมื่อ**ทุกคนในห้อง**ติ๊กแบบ ข. (มีคนเดียวไม่ยินยอม = ไม่บันทึกทั้งรอบ) ไมค์ปิด เก็บในโฟลเดอร์เข้ารหัสบนเครื่องเจ้าของ ไม่อัปโหลด ไม่ใช้ฝึกโมเดล
