## 1. ลักษณะการประมวลผล

ประมวลผลภาพ **ในเบราว์เซอร์ของอุปกรณ์ผู้ควบคุมข้อมูลเท่านั้น** (TF.js / MediaPipe / onnxruntime-web แบบ WASM) เฟรมกล้อง
อยู่ในหน่วยความจำ ไม่บันทึกวิดีโอ ไม่อัปโหลดภาพ ผลลัพธ์เก็บใน localStorage / sessionStorage / IndexedDB ของเบราว์เซอร์
(แยกตาม origin) ส่วน `server.py` (ถ้าใช้) อยู่ใน LAN ของร้าน ทำหน้าที่: รวมตัวเลขสรุปจากหลายเครื่อง, แปลง PDF, และเป็นตัวกลาง
ไปยัง AI ภายนอก 2 ราย ซึ่ง **ปิดเป็นค่าเริ่มต้น** หน้าเว็บทุกหน้าไม่โหลดทรัพยากรจากโดเมนภายนอก (ฟอนต์โฮสต์เอง, CSP ไม่อนุญาต
origin อื่น — ตรวจด้วย `tools/check-external.mjs`)

## 8. ความเสี่ยงคงเหลือและเงื่อนไขการดำเนินการ

1. **R1** — ชื่อ/เบอร์สมาชิกใน localStorage **ไม่ได้เข้ารหัสระดับแอป** → ต้องเข้ารหัสดิสก์และล็อกหน้าจอ (เงื่อนไขบังคับ)
2. **R2** — บูธ: ค่าเริ่มต้นจับคู่ผู้เข้าชมซ้ำด้วย descriptor → ถ้าเก็บความยินยอมรายบุคคลไม่ได้ ให้ใช้โหมดนับอย่างเดียว
   (ต้องเพิ่มสวิตช์ในซอฟต์แวร์ — **รายการงานถึงทีมกล้อง**) จนกว่าทนายสรุป L2
3. **R3** — ลูกจ้าง: ใช้การสแกนใบหน้าเป็นทางเลือกเท่านั้น มี QR/ลงชื่อมือ
4. **R9** — แต่งตั้งผู้รับผิดชอบรอบลบข้อมูลรายเดือน
5. ป้ายแจ้งครบทุกจุดกล้องก่อนเปิดระบบ (R6) · สัญญา DPA กับผู้ให้บริการ AI ก่อนเปิด M7/M8 (R7)

## 11. ภาคผนวก: Cloud backend — M16 สถิติการใช้งาน, M17 ระบบผู้ดูแล, M18 การชำระเงิน (ร่าง 2026-11)

> เพิ่มพร้อม `backend/` (Cloudflare Worker + D1) — **ไม่เปิดใช้จนกว่าผู้ควบคุมจะ deploy และตั้ง `LENSIQ_API_BASE`**
> สถาปัตยกรรมและการตั้งค่า: [`docs/BACKEND.md`](../BACKEND.md) · แผนรายได้/ภาษี/คืนเงิน: [`docs/BILLING-PLAN.md`](../BILLING-PLAN.md)
>
> *English: adds three processing activities run on Cloudflare (processor, possible transfer outside Thailand): opt-in
> coarse usage analytics (no IP/UA/images/text; raw events 90 days, aggregates kept, daily-rotated salt), the owner-only
> admin back office (audit log 400 days), and the PromptPay billing scaffold via Opn (off while FREE_MODE=true; tax
> records >= 5 years).*
