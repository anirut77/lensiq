# LENSIQ กล้องร้านค้า — รู้ว่าลูกค้าเข้าร้านกี่คน ซื้อกี่คน ช่วงไหน ยืนดูตรงไหน โดยไม่ส่งภาพขึ้นคลาวด์

**สำหรับร้านค้า SME: ใช้กล้องที่มีอยู่ ประมวลผลบนเครื่องในร้าน ไม่ส่งภาพขึ้นคลาวด์ ไม่บันทึกวิดีโอ**

หนึ่งใน 4 ผลิตภัณฑ์ของ LENSIQ (ดูดวง · กล้องร้านค้า · ชุดสัมภาษณ์ HR · Creative Suite) ที่ใช้เอนจินเดียวกัน
บัญชี Google เดียวกัน และหลังบ้านเดียวกัน · หน้าแรกของผลิตภัณฑ์: `retail.html` · ความแม่นยำ: `cameras.html#accuracy`

## ปัญหาของร้าน
- จัดพนักงานและโปรโมชันจากความรู้สึก เพราะไม่รู้จำนวนคนเข้าร้านจริงรายชั่วโมง
- รู้ยอดขาย แต่ไม่รู้ว่าคนเข้าร้าน 100 คน ซื้อกี่คน (อัตราการซื้อ)
- ไม่รู้ว่าป้ายหน้าร้าน ชั้นวาง หรือจอโฆษณาทำให้คนหยุดดูหรือไม่
- ระบบกล้องอัจฉริยะทั่วไปส่งภาพขึ้นคลาวด์ มีค่ารายเดือนต่อกล้อง และเสี่ยงเรื่อง PDPA

## สิ่งที่ได้
| ระบบ | ผลลัพธ์ |
|---|---|
| นับคนที่ประตู | นับคนเข้า–ออกด้วยเส้นนับ รายชั่วโมง กันพนักงานด้วยโซนพนักงาน |
| อัตราการซื้อ (conversion) | คนเข้าโซนแคชเชียร์ ÷ คนเข้าร้าน หรือเทียบกับจำนวนบิลจากหน้าคิดเงิน แสดงในแดชบอร์ดรายวัน |
| โซน คิว แผนที่ความร้อน | เวลาหยุดดูในแต่ละโซน ความยาวคิว ความหนาแน่น (ไม่มีภาพ ไม่มีรหัสบุคคล) |
| หลายกล้อง / หลายสาขา | มือถือหรือโน้ตบุ๊กหลายเครื่องรวมยอดเข้าเครื่องหลักผ่าน Wi-Fi ร้าน (ส่งเฉพาะตัวเลข ใช้ได้ฟรีวันนี้) · ⏳ รวมยอดหลายสาขาผ่านคลาวด์: เร็ว ๆ นี้ |
| LINE | ส่งลิงก์แดชบอร์ด/รายงานสรุปให้เจ้าของทาง LINE ได้เลย · การส่งสรุปรายวันเข้า LINE OA อัตโนมัติอยู่ในแผน (ยังไม่เปิด) |
| แดชบอร์ดรวม | สรุปรายวัน/สัปดาห์ เทียบช่วงเวลา พร้อมช่วงความเชื่อมั่น และป้าย “ข้อมูลยังไม่พอ” เมื่อตัวอย่างน้อย |
| ป้ายโฆษณาดิจิทัล | เวลาดู อัตรามอง เลือกคอนเทนต์ตามผู้ชม (ค่าประมาณอายุ/เพศปิดเป็นค่าเริ่มต้น) |
| จดจำสมาชิก (สมัครใจ) | จำลูกค้าประจำด้วยใบหน้าเฉพาะผู้ยินยอม เข้ารหัสในเครื่อง มีทางเลือกค้นด้วยเบอร์โทร |
| สแกนสินค้าด้วยกล้อง | คิดเงินแบบบริการตนเอง สต็อก และรายงานยอดขาย |

## ความแม่นยำที่เผยแพร่ (ไม่อวดเกินจริง)
- **ผลวัดบนวิดีโอสาธารณะ** (`ACCURACY.md` ข้อ 1): ฉากที่คล้ายประตูร้าน ยอดสุทธิคลาดเคลื่อน +3.2% ความแม่นของเหตุการณ์ 93% · ฝูงชนหนาแน่นคลาดเคลื่อนได้ −28% ถึง +19% — จึงแนะนำกล้องสูงเหนือประตู และคนสูงอย่างน้อย 1/4 ของภาพ
- **ตรวจความแม่นยำหน้างาน** ในหน้า `store.html`: พนักงานกด “+ เข้า / + ออก” ตามจริงช่วงสั้น ๆ ระบบเทียบกับตัวนับของตัวเอง แสดงผลพร้อมช่วงความเชื่อมั่น 95% และค่าที่แนะนำ — ประมวลผลในเครื่อง ไม่เก็บภาพ
- **ทดลองหน้าร้าน 2 สัปดาห์** เทียบกับการนับด้วยคน เกณฑ์ยอมรับ เช่น ยอดรายวันคลาดเคลื่อน ≤ 5% (`docs/PILOT-PLAN.md`)
- กล้องแจ้งเมื่อภาพมืด/เบลอเกินกว่าตัวเลขจะเชื่อถือได้

## ทำไมเชื่อถือได้
- **PDPA ตั้งแต่ต้น:** ป้ายแจ้งการใช้กล้องพิมพ์ได้ 3 ภาษา แม่แบบ DPIA/ROPA ข้อความขอความยินยอม (ต้องให้ฝ่ายกฎหมายของร้านตรวจทาน)
- **ไม่มีค่าคลาวด์ต่อกล้อง** เปิดในเบราว์เซอร์ ใช้ได้แม้ออฟไลน์

## แพ็กเกจ (ฉบับร่าง — `docs/BILLING-PLAN.md`)

| Creator (ครีเอเตอร์) | 990 บาท/เดือน | ร้านเดียว ผู้ช่วยเขียน 100 ครั้ง/เดือน ตอบกลับภายใน 2 วันทำการ · ⏳ ประวัติบนคลาวด์ 90 วัน · ⏳ ฮับ 3 จุด (ส่งออก CSV บนเครื่องใช้ได้ฟรีอยู่แล้ว) |

| องค์กร | ใบเสนอราคา | ติดตั้งในเครือข่ายภายใน DPA ตามมาตรา 40 SLA ตามสัญญา |

ราคาเป็นฉบับร่างจนกว่าจะเปิดขาย — ยืนยันในใบเสนอราคา · ⏳ = เร็ว ๆ นี้ (ยังไม่เปิด ไม่รวมอยู่ในข้อเสนอจนกว่าจะส่งมอบได้จริง) · ระหว่างนี้ขายผ่านใบเสนอราคาและโครงการนำร่อง 2 สัปดาห์ (ค่าตั้งค่า อบรม และสรุปผลที่ลงนามร่วมกัน) ไม่ใช่แพ็กเกจบริการตนเอง

**ขั้นตอนถัดไป:** สำรวจหน้างาน 1 วัน → ทดลอง 2 สัปดาห์ → รายงานผลที่ลงนามร่วมกัน
